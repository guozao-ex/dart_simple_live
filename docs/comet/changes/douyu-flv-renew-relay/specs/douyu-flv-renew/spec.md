# 斗鱼 FLV 续流（douyu-flv-renew）

## 目的

斗鱼对第三方客户端的 FLV 直链按固定寿命掐线：实测同一地址存活 300.1~300.4s，与带宽、码率、CDN 无关，部分线路即使地址里没有 expire 参数也同样准时断开。官方网页端的做法是每约 300 秒重新签名续流。本 capability 提供一个对播放器完全透明的本机中继，在到期前预取新地址并在 FLV tag 边界无缝续接，同时给用户一个可关闭的开关。

## 行为要求

### 取址与续期

- 续流时需要重新拉取 homeH5Enc 脚本并重新签名，再调用 getH5Play 取址；不得复用进房时那份已签名 data（签名时间戳可用窗口约 5 分钟）。
- 续期成功的地址要回写为该线路的当前地址，供后续会话复用；距离上次取址超过"预期寿命减提前量"时，新会话必须先续期再连接，续期失败才退回旧地址。

### 中继形态

- 中继在本机回环地址上监听随机端口，为每条线路暴露一个固定地址交给播放器；播放器不需要携带任何请求头。
- 上游请求头取自播放地址自带的 headers；上游响应头超时 8 秒，连续 15 秒无数据按断流处理。
- 中继地址不参与"强制 HTTPS"改写。

### 续接算法

- 到期前 5 秒开始预取同房间、同画质、同线路的新地址并建立第二条连接。
- 触发切换的时机有两个：连接存活达到预期寿命（主动换流，不依赖上游是否真的掐线），以及上游结束或判死（被动续接）。
- 拼接时丢弃新连接的 FLV 文件头、onMetaData 与 sequence header，从"已转发位置之后的第一条视频关键帧"接上；没有视频关键帧的流退化取第一条不落后于转发位置的 tag；整条流时间轴回退时重设基准后再从关键帧接。
- 编码配置只在确实变化时补发，且只取切换点之前的配置；补发的配置 tag 时间戳与切片一起偏移并钳制。
- 输出时间戳必须单调不减；旧连接中尚未转发的 tag 先按原样发完，等待新流关键帧期间继续转发旧连接的数据，保证换流不产生 GOP 级空洞。
- 播放器断开或中继关闭时，当前连接与预取连接都要被释放。

### 失败与回落

- 首次连接失败、上游不是 FLV 时，向播放器返回 502 并结束会话，不能返回 200 空响应。
- 续流取址失败或新地址不是 FLV 时，保留当前连接继续播放，并按退避重试（15s 起、上限 5 分钟）；上游已经断开且补连失败时，会话结束，由播放器侧的错误/重试逻辑接手。
- 单条线路登记失败不影响其他线路；一条线路都没能接入中继时，播放地址保持原始直连地址。

### 用户开关

- 开关默认开启；关闭后斗鱼播放不接入中继（不建立监听端口、不调用续流取址），继续走既有播放路径。
- 关闭后保留既有的 270 秒定时换流兜底；启用中继时该定时器停用，避免多余的画面抖动。

### 平台边界

- 仅斗鱼提供续流取址回调；其他平台的播放地址不带该回调，行为与本 capability 无关。
- 只有看起来是 FLV 的线路会接入中继，HLS 线路原样交给播放器。

## 场景

### Scenario: 关闭开关时斗鱼播放不接入中继

验收：A1

前提：用户关闭斗鱼续流开关。当调用方以 enabled 为 false 接入播放地址时，中继不被创建：不绑定任何本地端口，也不调用续流取址。预期：接入函数返回空结果，调用方继续使用原始直连地址；播放本身不受影响。

### Scenario: 开关默认开启

验收：A2

前提：用户没有改过该设置。预期：两端设置项初始值为真；core 接入函数的默认参数也为真，即默认走中继。

### Scenario: 到期自动续接且既有用例全过

验收：A3

前提：中继已在播放中，上游连接存活到达预期寿命，且预取连接已就绪。当发生换流时，输出流保持连续：时间戳不倒退、不出现 GOP 级空洞。预期：既有续流用例（含假 CDN 端到端）全部通过。

### Scenario: 真实斗鱼流跨过 300 秒租约

验收：A6

前提：以真实房间号开启浸泡测试并运行 360 秒。预期：续流取址至少 1 次，视频帧最大间隔小于 1000 毫秒，时间戳零倒退，全程不断流。

### Scenario: 三个包静态检查零问题

验收：A4

在 simple_live_core、手机端与 TV 端分别执行 dart analyze 与 flutter analyze。预期：三处均报告无问题。

### Scenario: Windows 桌面原生构建成功

验收：A5

执行 Windows 桌面 release 构建。预期：构建成功并产出可运行的产物目录。

### Scenario: 断流续接与失败回落

验收：A3

前提：上游连接在预期寿命前意外结束。预期：中继优先使用预取连接续接；没有预取连接时同步补取，一次失败后再补一次，两次都失败才结束会话，且不会把会话挂死。
