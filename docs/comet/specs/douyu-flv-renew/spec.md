# 斗鱼 FLV 续流（douyu-flv-renew）

## 目的

斗鱼对第三方客户端的 FLV 直链按固定寿命掐线（实测 300.1~300.4s）。本 capability 提供对播放器透明的本机续流中继、用户开关，以及中继不可用时的定时换流兜底。本版把兜底的调度策略抽成 core 中可测的独立单元，并由两端复用。

## 行为要求

### 取址与续期

- 续流时需要重新拉取 homeH5Enc 脚本并重新签名，再调用 getH5Play 取址；不得复用进房时那份已签名 data（签名时间戳可用窗口约 5 分钟）。
- 续期成功的地址要回写为该线路的当前地址，供后续会话复用；距离上次取址超过「预期寿命减提前量」时，新会话必须先续期再连接，续期失败才退回旧地址。

### 中继形态

- 中继在本机回环地址上监听随机端口，为每条线路暴露一个固定地址交给播放器；播放器不需要携带任何请求头。
- 上游请求头取自播放地址自带的 headers；上游响应头超时 8 秒，连续 15 秒无数据按断流处理。
- 中继地址不参与「强制 HTTPS」改写。

### 续接算法

- 到期前 5 秒开始预取同房间、同画质、同线路的新地址并建立第二条连接。
- 触发切换的时机有两个：连接存活达到预期寿命（主动换流），以及上游结束或判死（被动续接）。
- 拼接时丢弃新连接的 FLV 文件头、onMetaData 与 sequence header，从「已转发位置之后的第一条视频关键帧」接上；没有视频关键帧的流退化取第一条不落后于转发位置的 tag；整条流时间轴回退时重设基准后再从关键帧接。
- 编码配置只在确实变化时补发，且只取切换点之前的配置；补发的配置 tag 时间戳与切片一起偏移并钳制。
- 输出时间戳必须单调不减；旧连接中尚未转发的 tag 先原样发完，等待新流关键帧期间继续转发旧连接的数据，保证换流不产生 GOP 级空洞。
- 播放器断开或中继关闭时，当前连接与预取连接都要被释放。

### 失败与回落

- 首次连接失败、上游不是 FLV 时，向播放器返回 502 并结束会话，不能返回 200 空响应。
- 续流取址失败或新地址不是 FLV 时，保留当前连接继续播放，并按退避重试；上游已经断开且补连失败时结束会话。
- 单条线路登记失败不影响其他线路；一条线路都没能接入中继时，播放地址保持原始直连地址。

### 用户开关

- 开关默认开启；关闭后斗鱼播放不接入中继（不建立监听端口、不调用续流取址），继续走既有播放路径。
- 关闭后由定时换流兜底接管：每 270 秒重新取一次地址，避免流地址到期后断流。

### 定时换流兜底（本版抽取为可测单元）

- 兜底调度器位于 core，可配置间隔（默认 270 秒），由调用方注入「是否应当换流」的判定与换流回调，提供启动、停止与运行状态查询。
- 每次触发都先询问判定：判定为假（例如中继已接入、应用在后台、直播间未开播）时跳过本次，不产生任何副作用。
- 启动是幂等的：重复启动不会产生第二个定时器；停止后不再触发。
- 调度器不感知业务原因，只按调用方给出的判定执行；两端直播间控制器各自持有一个实例，生命周期跟随页面，退出时停止。

### 平台边界

- 仅斗鱼提供续流取址回调；其他平台的播放地址不带该回调，行为与本 capability 无关。
- 只有看起来是 FLV 的线路会接入中继，HLS 线路原样交给播放器。

## 场景

### Scenario: 兜底调度器按间隔触发

验收：A1

以测试间隔启动调度器并推进虚拟时间。预期：回调在每次到达间隔时触发一次，次数与推进时长严格对应。

### Scenario: 判定为假时跳过

验收：A2

判定回调返回 false 期间推进虚拟时间。预期：换流回调零调用；判定恢复为真后，按间隔正常触发。

### Scenario: 停止与幂等启动

验收：A3

重复调用启动，再推进时间；随后停止并继续推进时间。预期：重复启动只产生单一触发序列（不重复触发）；停止后不再触发。

### Scenario: 自定义间隔

验收：A4

以非默认间隔构造调度器并推进时间。预期：触发节奏跟随自定义间隔，而不是默认的 270 秒。

### Scenario: 两端复用调度器

验收：A5

手机端与 TV 端直播间控制器都改为持有兜底调度器实例：进入直播时启动、离开页面时停止，判定条件与改动前等价（中继接入时跳过、后台或未直播跳过）。预期：控制台/代码层面不再有各自的定时循环实现，且三个包静态检查零问题。

### Scenario: 全部用例与原生构建通过

验收：A6

运行 core 全部用例（含新增调度器用例）与 Windows release 构建。预期：用例全部通过，构建成功。
