# 弹幕横向滚动引擎（danmaku-scroll-engine）

## 目的

为 `packages/canvas_danmaku` 提供与 Fy1Sync 等价的横向弹幕调度、运动与交互模型：消息到达时零排版、零光栅化，只在每帧按空闲车道批量生成；所有滚动弹幕等速，车道在前一条尾部清出右边缘后立即复用；没有空车道时丢弃而不是堆叠；文本位图按样式缓存并安全淘汰；同文本在 8 秒窗口内合并为 `×N`；悬停或点击可暂停单条弹幕并弹出操作菜单。`simple_live_app` 与 `simple_live_tv_app` 共用该引擎，公开 API 向后兼容。

## 输入与生命周期

- 引擎接收 `DanmakuContentItem<T>`，按 `DanmakuItemType` 分流为滚动、顶部、底部、特效；本规格的调度规则针对滚动弹幕，其他类型保持现有语义。
- `DanmakuContentItem` 可携带 `userName`（菜单展示）与 `mergeCount`（合并计数）；现有 `count` 字段语义不变。
- `DanmakuController.addDanmaku` 只把内容压入到达队列，不创建 Paragraph、不创建 `ui.Image`、不查车道。
- 到达队列容量 2000；溢出时丢弃最旧的消息并累计 `dropped`。
- 帧循环只在到达队列或在屏条目非空时运行；清屏、暂停、恢复、切后台沿用现有外部行为。
- 每帧顺序固定为：推进帧时间 → 取出到达队列并处理合并 → 计算空闲车道 → 批量生成 → 清理越界条目。

## 批量生成

- 每帧最多生成 `min(freeLanes, maxSpawnPerFrame)` 条滚动弹幕，`maxSpawnPerFrame` 默认 8。
- 取得车道的消息才创建 Paragraph 与位图；未取得车道的消息直接丢弃并计入统计，不留在队列等下一帧。
- `selfSend` 与 `massiveMode` 保留现有优先/叠轨语义：`massiveMode` 打开时无空车道可随机选一条车道叠加，不受丢弃规则限制。
- 顶部/底部弹幕使用独立的固定槽位分配：有空槽才生成，`staticDuration` 到期移除。

## 速度与车道

- 滚动速度由设置项 `duration`（秒）换算：`speed = viewWidth / durationMs`（px/ms），所有滚动弹幕共享该速度。
- 车道数 `laneCount = floor(viewHeight * area / laneHeight)`，`laneHeight` 由字号与 `lineHeight` 决定；`safeArea` 规则保持不变。
- 车道分配记录 `freeAt[lane]`：生成宽度为 `w` 的弹幕时 `freeAt[lane] = now + w / speed`，`freeAt <= now` 即空闲。
- 条目位置由帧时间纯函数给出：`x(t) = from - (t - startTick) * speed`，`from` 为生成时的视口宽度；`x + width < 0` 视为越界并移除。
- 速度设置变化时，在屏条目重算 `startTick` 保持当前位置连续，`freeAt` 的剩余等待按 `oldSpeed / newSpeed` 缩放。
- 视口变窄时，所有忙碌车道的 `freeAt` 追加 `(oldWidth - newWidth) / speed`，避免新弹幕撞上尚未清出的尾部。
- 字号、字重、字体、描边或设备像素比变化时，清理在屏条目与位图缓存并重新计算车道；仅视口尺寸变化时保留在屏条目。

## 合并计数

- 开关 `mergeDuplicates` 默认开启；关闭时每条消息独立显示，合并组清空。
- 合并组以文本为键，忽略颜色、用户名与平台；容量 2000，超出时淘汰最旧组。
- 窗口为 8 秒，按帧时间计算：组创建时记录到期时间；到期后删除，同文本再次出现时从 1 重新计数。
- 窗口内同文本重复到达时：
  - 若原条目仍在屏，递增其 `mergeCount`，按新计数重新生成位图并更新宽度，保持当前位置与 `startTick` 不变，同时把车道 `freeAt` 延长 `(newWidth - oldWidth) / speed`。
  - 若原条目已离屏，递增组计数但不生成新条目（该条消息不显示）。
- 已有 `count`（平台聚合弹幕）的内容不参与合并，直接入队。
- `×N` 以文本后缀渲染，字号为主字号的 0.8 倍、同色；位图缓存键包含 `mergeCount`。
- 清屏、切换直播间、关闭合并开关时清空合并组。

## 位图缓存

- 缓存键包含：文本、颜色、字号、字重索引、字体族、描边宽度、设备像素比、`selfSend`、`count`、`mergeCount`、`isColorful`。
- 条目保存 `ui.Image`、逻辑宽高与引用计数；命中时直接使用已保存尺寸，不再做 Paragraph 排版。
- 缓存按最近最少使用淘汰，预算 24 MiB 且最多 512 条；引用计数大于 0 的条目不得淘汰。
- 引擎在条目越界移除时释放引用；缓存独占 `ui.Image` 的释放权，`DanmakuItem` 不得直接释放共享位图。
- 样式或设备像素比变化时清空缓存与在屏条目，清空后不得再引用旧位图。

## 绘制与帧调度

- 使用单个 `Ticker` 维护帧时间，`ValueNotifier<int>` 作为 `CustomPainter` 的 `repaint` Listenable；帧推进不重建 `CustomPaint`、不新建 painter 实例。
- painter 在绘制时读取当前帧时间并计算位置，不在 `paint` 中累加可变状态；同一 tick 重复绘制结果一致。
- 绘制位图时把横坐标吸附到设备像素网格（`round(x * dpr) / dpr`），减少逐帧重采样造成的文字抖动。
- 顶部/底部/特效弹幕复用同一帧时间与重绘通道；特效弹幕的动画参数保持现有实现。

## 暂停与菜单

- 命中判定只覆盖条目矩形：用当前帧时间计算条目位置后做矩形命中；非条目区域不参与命中，指针事件继续传给下层播放器控件。
- 桌面指针悬停到条目上，或触屏点击条目时，冻结该条：记录 `heldAt`，位置在暂停期间保持不变；同一时间只允许一条弹幕处于暂停。
- 暂停时把该条所在车道的 `freeAt` 延长到剩余行程结束之后，避免新车道的弹幕撞上暂停条目；恢复时按当前剩余行程重算 `freeAt`。
- 菜单显示在条目下方；下方空间不足时显示在上方；水平方向限制在视口内，不遮挡条目本体。
- 菜单内容：用户名（内容携带时）、`复制`、`屏蔽此弹幕`、`关闭`。
  - `复制` 把原文写入系统剪贴板并关闭菜单、恢复条目。
  - `屏蔽此弹幕` 把原文交给宿主写入现有 `shieldList`，移除所有同文本在屏条目并关闭菜单。
  - `关闭` 关闭菜单并恢复条目。
- 指针移出条目与菜单的并集后等待 220 毫秒再恢复；期间回到条目或菜单则取消恢复。点击菜单外的空白区域同样关闭菜单并恢复。
- 暂停/恢复只影响被命中的条目，不暂停其他弹幕或视频播放。

## 应用侧开销

- 屏蔽关键词列表变化时预编译并缓存 `Pattern` 列表；处理单条消息只做匹配，不新建 `RegExp`。
- 聊天列表自动滚动合并为每帧最多一次 post-frame 回调；列表裁剪与自动滚动开关语义不变。
- 直播消息处理、弹幕协议与平台客户端除「内容携带用户名」外保持原样。

## 统计与可观测

- 引擎暴露只读统计：`queued`、`spawned`、`dropped`、`cacheHits`、`cacheMisses`、`visible`、`merged`。
- 统计只在调试模式读取或打印，不影响生产路径与用户界面。

## 平台边界

- `simple_live_app` 与 `simple_live_tv_app` 共用同一引擎；公开类型与方法签名向后兼容。
- 两个 App 的弹幕设置页继续通过 `DanmakuOption` 传入配置；合并开关在手机端设置页提供，TV 端使用默认值。
- 菜单只映射仓库已有能力：复制、屏蔽此弹幕、关闭；不实现收藏、回复、禁言、用户详情、历史。
- Windows 为本次验证平台；其他平台依赖 Flutter 同一渲染路径，不单独引入平台分支。

## 场景

### Scenario: 到达只入队

验收：A1

在未推进帧的情况下连续向控制器加入 1000 条滚动弹幕。预期：Paragraph 与位图构建计数保持 0；到达队列长度与容量上限一致（超过 2000 时丢最旧）；推进一帧后才为取得车道的消息创建位图。

### Scenario: 每帧批量与丢弃

验收：A2

构造 10 条空闲车道并在一帧内加入 100 条滚动弹幕。预期：本帧生成的滚动条目不超过 `min(10, maxSpawnPerFrame)`；其余计入 `dropped`；默认模式下同车道任意两条的可见区间不重叠；打开 `massiveMode` 后允许在无空车道时叠轨。

### Scenario: 等速与车道复用

验收：A3

生成两条长度不同、起点相同的滚动弹幕并推进同一段时间。预期：两条的横向位移（px）相同，即 px/s 相同；第一条尾部清出右边缘后，同车道立即可以分配给下一条；分配器单测覆盖 `freeAt` 的分配、复用、`rescale`、`delay`、`extend` 与车道数变化。

### Scenario: 变速与尺寸变化

验收：A4

在屏存在滚动弹幕时修改 `duration`，随后改变视口宽度并暂停/恢复。预期：变速瞬间条目的屏幕位置连续、不跳变；车道剩余等待按旧/新速度比例缩放；视口变窄后新弹幕不会撞上旧尾部；暂停期间位置冻结，恢复后从冻结处继续。

### Scenario: 位图缓存与所有权

验收：A5

用相同文本与样式连续生成两条弹幕，再用不同字号生成一条。预期：相同样式第二次命中缓存、Paragraph 构建计数不增加；不同字号不串图；强制淘汰仍在屏的条目时其位图不被释放；修改字号/字重/字体/描边/DPR 后缓存清空、在屏条目清理，无 use-after-dispose；稳态缓存占用不超过 24 MiB。

### Scenario: 每帧重绘不重建 widget

验收：A6

连续推进 60 帧。预期：painter 的绘制次数为 60，`CustomPaint`/painter 实例创建计数不增加；同一帧时间重复绘制得到相同位置。

### Scenario: 设置与平台回归

验收：A7

切换字号、字重、字体、描边、区域、速度、不透明度、上下边距与合并开关，并触发顶部/底部/特效弹幕、清屏与切后台。预期：各设置生效且与改动前一致；`simple_live_app`、`simple_live_tv_app` 静态分析通过；Windows release 构建成功。

### Scenario: 应用侧洪峰开销

验收：A8

保持屏蔽关键词列表不变，连续处理多条聊天消息，并频繁触发聊天自动滚动。预期：每条消息的处理不新建 `RegExp`；同一帧内自动滚动最多执行一次；相关计数测试通过。

### Scenario: 帧预算与 profile 指标

验收：A9

以超过空闲车道数的速率注入滚动弹幕。预期：任一帧的 Paragraph/位图构建次数不超过 `maxSpawnPerFrame`；Windows profile 下密集房间连续 60 秒的 FrameTiming 摘要显示 UI p95 ≤ 8ms，且没有超过 16.7ms 的 UI/Raster 帧。

### Scenario: 合并计数

验收：A10

在 8 秒窗口内连续加入 3 条相同文本，随后跨过窗口再加入 1 条；分别验证开关开启与关闭。预期：开启时只生成一个在屏条目并显示 `×3`，计数增加时位图与宽度更新且位置不跳变、车道占用同步延长；跨过窗口后重新生成条目并从 1 计数；关闭开关后每条消息各自显示；带 `count` 的聚合弹幕不参与合并。

### Scenario: 悬停/点击暂停与菜单

验收：A11

用鼠标悬停或用触屏点击一条在屏弹幕，再点击菜单项与空白区域。预期：条目冻结并显示包含用户名、复制、屏蔽此弹幕、关闭的菜单；移出条目与菜单 220ms 后恢复；复制写入剪贴板；屏蔽后同文本在屏条目移除并写入屏蔽列表；非条目区域的指针事件仍到达播放器控件；暂停期间同车道不会生成重叠的新条目。
